SORDEX API 参考API Reference

概览

SORDEX 是 BSC 主网（chainId 56）上的非托管现货订单簿 DEX。对接分三层：

  • 公开数据 REST / WebSocket：交易对、盘口、成交、K 线、聚合商标准数据。只读，无需鉴权。
  • 链上合约：挂单、撤单、改价、吃单、建对、做市金库充提，直接调合约，由钱包私钥签交易。资金安全只由链上保证。
  • 签名报价（做市）：做市商用 EIP-712 离线签名报价提交到撮合层，改价零 gas；资金锁在做市金库，成交时原子交割。
读接口返回的是缓存视图，用于展示与路由，不作为资金真相；资金状态以链上为准。

Overview

SORDEX is a non-custodial spot order-book DEX on BSC mainnet (chainId 56). Integration spans three layers:

  • Public REST / WebSocket: pairs, order book, trades, candles, aggregator feeds. Read-only, no auth.
  • On-chain contracts: placing, cancelling, amending, taking, listing and vault deposits/withdrawals call contracts directly, signed by your wallet key. Fund safety is guaranteed only on-chain.
  • Signed quotes (market making): makers post EIP-712 off-chain quotes to the matching layer; repricing is gasless. Funds stay in the vault and settle atomically on fill.
Read endpoints return cached views for display and routing, not the source of truth for funds; fund state is authoritative on-chain.

WebSocket

WS/ws无鉴权
实时推送，无需轮询。消息有三种：{type:"hello", …统计}（连接成功即收，重连后也会收到）；{type:"update", block, pairs}（盘口、成交或做市报价有变化；pairs 是受影响的交易对 id 数组，null 表示全部），收到后再用 REST 拉取你关心的数据；{type:"hb"}（每 25 秒一次心跳，超过 70 秒没收到任何消息请主动重连）。同一 IP 最多 20 条连接；断线请指数退避重连，重连成功后先拉一次最新数据以补上断线期间的变化。
const ws = new WebSocket("wss://sordexpro.com/api/ws");
ws.onmessage = (e) => {
  const ev = JSON.parse(e.data);
  // { type:"hello" } | { type:"update", block, pairs:["1"]|null } | { type:"hb" }
  if (ev.type === "update") { /* 再用 REST 拉取变化的数据 */ }
};

WebSocket

WS/wsno auth
Live push, so you do not need to poll. };

做市商接入模型

做市商有两种资金托管模式，报价准入规则不同：

  • 金库做市（VAULT）：把流动性充入 MMCollateralVault。该 maker 在对应交易对金库有可用余额时，报价无需 API Key。
  • 授权额度做市（ALLOWANCE）：资金留在钱包、只对合约 approve。此模式报价必须带 API Key。

API Key 为自助申领：用资金地址 EIP-712 签名即时领取，绑定 maker 地址 + IP 白名单。Key 只是报价准入凭证，不托管资金、不能提现、不能替别的地址报价。详见 报价准入。

Market-making access model

Makers run under one of two custody modes, with different quote-admission rules:

  • Vault custody (VAULT): deposit liquidity into MMCollateralVault. When the maker has available balance in the pair's vault, quoting needs no API key.
  • Allowance custody (ALLOWANCE): funds stay in the wallet with an on-chain approval. Quoting in this mode requires an API key.

Keys are self-issued: sign once with EIP-712 from the funding address to receive one, bound to the maker address + an IP allowlist. A key is a quote-admission credential only — it custodies no funds, cannot withdraw, and cannot quote for another address. See quote admission.

交易 API 概览

交易 API 和做市报价共用同一把 API Key，Key 代表它绑定的那个钱包。下单、撤单、查询都用这一把 Key，不需要另外申请。

平台不托管资金，也不替你付 gas。下单类接口返回一笔算好的交易（to / data / value），由你的程序用 Key 绑定的钱包签名并广播，gas 由你自己付。资金始终在你自己的钱包里，成交与保护由合约强制执行。

类型怎么成交
市价单服务端按当前盘口（链上挂单 + 做市签名报价）规划路由，组装一笔聚合吃单交易，带"最少到手量"。盘口在你发交易时变差、到手会低于最少到手量的，整笔回滚，不会以意外的价格成交。
限价单 GTC挂到链上订单簿，挂单时锁仓（买单锁 USDT，卖单锁代币）。和对面的单价格交叉后由撮合程序自动成交，撤单时退回锁仓。只能挂不会立即成交的价格：限价已经够得着对面最优价时，接口返回 WOULD_CROSS，请先用 IOC 吃单，剩下的再挂。这是为了防止挂上去的单被人按你的限价、而不是盘口更好的价格成交。
限价单 IOC只按你的限价吃盘口上现有的单，吃不到的部分不留单。

Trading API overview

The trading API uses the same API key as market-maker quoting. The key represents the wallet it is bound to, and covers placing orders, cancelling and queries. There is nothing extra to apply for.

The platform never holds your funds and never pays gas for you. Order endpoints return a ready-made transaction (to / data / value). Your program signs and broadcasts it from the wallet bound to the key and pays the gas. Funds stay in your own wallet, and the contracts enforce settlement and protections.

typehow it fills
MarketThe server plans a route across the current book (on-chain orders plus market-maker signed quotes) and builds one aggregated take transaction with a minimum amount out. If the book moves and you would receive less than that minimum, the whole transaction reverts, so you never fill at an unexpected price.
Limit GTCRests on the on-chain order book with funds locked (USDT for buys, tokens for sells). It fills automatically when it crosses the other side, and cancelling returns the locked funds. GTC only accepts prices that would not trade immediately: if your limit already reaches the best price on the other side, you get WOULD_CROSS. Send IOC first and rest the remainder. This stops a resting order from being filled at your own limit instead of the better book price.
Limit IOCTakes only what is on the book at or better than your limit price. Nothing rests.
Headerx-api-key
Every request needs x-api-key: sdx_mk_… (x-mm-key also works), and must come from an IP on that key's allowlist. Each key can make up to 600 requests per minute.

Quantities are integer strings in the token's smallest unit (for an 18-decimal token, 1 token = 1000000000000000000). Prices are decimal strings: how many USDT one base token is worth.

Errors return { error, message, messageZh }: error is a stable code for your program, the other two are explanations in English and Chinese.

报价准入

/quote 与 /quote/batch 按以下顺序放行（quote.maker 为准入主体）：

  • 已被平台停用的地址：一律拒收，返回 403。
  • 金库做市：maker 为 VAULT 模式且在该交易对金库有可用余额 → 直接放行，无需 Key。
  • 其余情况：请求头须带有效 x-mm-key，且满足：Key 处于 active、Key 绑定地址 == quote.maker、请求来源 IP 在该 Key 的白名单内。

读链失败或取不到金库余额时保守落到 Key 校验（fail-closed）。违反任一条返回 401/403，错误文案指明原因。

通过准入后，入池还有两条资金规则（防止用尘埃报价占满报价池）：

  • 单张最小额：每张报价的成交额（数量 × 价格）至少 0.5 USDT，低于此返回 BELOW_POOL_MIN_NOTIONAL。链上最小额更低，但报价池按这个门槛收。
  • 资金覆盖：同一 maker、同一交易对、同一方向，池内报价加上本张的总量不得超过可用资金（卖单看 base，买单看 USDT；VAULT 模式为金库可用额，ALLOWANCE 模式为授权额与钱包余额的较小值）。超出返回 NOT_COVERED；暂时读不到资金返回 BUDGET_UNKNOWN，稍后重试即可。超出资金的报价本来也进不了盘口，所以先撤掉一些再补。

pairId 及各数值字段会统一成十进制字符串（例如 "01" 与数字 1 都按 "1" 处理），签名与 hash 不受影响。

Quote admission

/quote and /quote/batch admit in this order (the subject is quote.maker):

  • Addresses suspended by the platform are always rejected with 403.
  • Vault custody: a VAULT-mode maker with available balance in the pair's vault is admitted directly, no key needed.
  • Otherwise: the request must carry a valid x-mm-key that is active, whose bound address equals quote.maker, and the request's source IP must be in that key's allowlist.

If chain reads or vault-balance lookups fail, admission falls back to the key check (fail-closed). Any violation returns 401/403 with an error message stating the cause.

Once admitted, two funding rules apply before a quote enters the pool (so the pool can't be filled with dust):

  • Minimum size: each quote must be worth at least 0.5 USDT (size × price), otherwise you get BELOW_POOL_MIN_NOTIONAL. The on-chain minimum is lower, but the pool applies this floor.
  • Funds must cover the quotes: for the same maker, pair and side, the quotes already in the pool plus this one may not exceed the available funds (base for asks, USDT for bids; the vault balance in VAULT mode, or the lower of allowance and wallet balance in ALLOWANCE mode). Going over returns NOT_COVERED; if funds can't be read right now you get BUDGET_UNKNOWN and can simply retry. Quotes beyond your funds would never show on the book anyway, so cancel some before adding more.

pairId and the numeric fields are normalized to decimal strings (for example "01" and the number 1 are both treated as "1"); signatures and hashes are unaffected.

代理自动挂单

持续自动挂单时，无法每档都用钱包弹窗签名。做市商可一次性授权一个代理地址，由本地进程用代理私钥自动签报价——代理只能签报价，碰不到提现。

  • 1. 存保证金：MMCollateralVault.deposit(token, amount)，资金锁在金库、只由你自己提。
  • 2. 一次性授权：本地生成代理地址，用做市商钱包对 Settler 调 setAgent(agent, expiry)（expiry 为授权到期秒级时间戳，传 0 撤销）。
  • 3. 本地自动签：进程用代理私钥 EIP-712 签每档、提交 /quote 或 /quote/batch。报价 maker 仍填做市商地址；后端识别签名人为已授权代理即放行。
// 一次性授权（做市商钱包发起）
SignedQuoteSettler.setAgent(agentAddress, expiryUnixSeconds)
// 查询授权
SignedQuoteSettler.isAuthorizedAgent(maker, agent) -> bool
代理私钥泄露最坏情况仅限「在金库额度与价格范围内乱签报价」，不能提现；授权带 expiry 自动到期，可随时 setAgent(agent, 0) 撤销。

Agent quoting

Continuous quoting cannot pop a wallet prompt per level. A maker authorizes an agent address once, then a local process signs quotes with the agent key automatically — the agent can only sign quotes, never withdraw.

  • 1. Fund the vault: MMCollateralVault.deposit(token, amount); funds stay locked and only you withdraw.
  • 2. Authorize once: generate an agent address locally and call setAgent(agent, expiry) on the Settler from the maker wallet (expiry = unix seconds; 0 revokes).
  • 3. Auto-sign locally: the process EIP-712-signs each level with the agent key and posts to /quote or /quote/batch. The quote's maker stays the maker address; the backend admits once it sees the signer is an authorized agent.
// one-time authorization (from the maker wallet)
SignedQuoteSettler.setAgent(agentAddress, expiryUnixSeconds)
// check authorization
SignedQuoteSettler.isAuthorizedAgent(maker, agent) -> bool
Worst case if the agent key leaks is bounded to signing bad quotes within your vault budget and price range — it cannot withdraw; authorization auto-expires and can be revoked anytime via setAgent(agent, 0).

项目方交易税

项目方交易税由项目方自管，平台不代管、不设置。推荐实现识别标志 sordexTax()，使 SorDex 上与 AMM 一致地买扣一次、卖扣一次（扣的是 base）。

// 代币实现此接口，声明买/卖税率(bps,100=1%)与收款地址
function sordexTax() external view
  returns (uint16 buyBps, uint16 sellBps, address recipient);

对接两步：① 在代币实现 sordexTax()；② 把 SorDex 的订单簿 / 金库 / 结算合约加入代币自身转账税免税白名单。否则 base 进出合约两跳会各被原生税抽一次。单侧税率上限 20%，计价币 USDT 全程不抽税。未实现 sordexTax() 的普通抽税币仍可交易（按实际到账记账，会被抽两次）。

Project transfer tax

A project's transfer tax is self-managed; the platform neither sets nor custodies it. Implement the sordexTax() marker so that on SorDex the tax is charged once per buy and once per sell (deducted in base), like an AMM.

// token implements this to declare buy/sell rates (bps, 100=1%) and recipient
function sordexTax() external view
  returns (uint16 buyBps, uint16 sellBps, address recipient);

Two steps: (1) implement sordexTax() in the token; (2) add SorDex's order-book / vault / settler contracts to the token's own fee-exemption list — otherwise the native tax fires on both hops as base moves in and out of the contract. Per-side cap is 20%; the quote currency USDT is never taxed. Plain fee-on-transfer tokens without sordexTax() still trade (accounted by actual received amount, taxed twice).
